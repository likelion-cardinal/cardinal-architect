MySQL 백업 CronJob (mysqldump → S3)
======================================================================
(이 디렉토리에서 실행)

선행 조건 — terraform
----------------------------------------------------------------------
노드 Role 의 S3 권한이 etcd/ 와 pki/ prefix 로만 묶여 있어서, 그대로 두면
업로드가 AccessDenied 로 실패한다. 아래가 apply 되어 있어야 한다.

  terraform apply -var-file=env/prod.tfvars

  변경되는 것 (신규 리소스 없음, 둘 다 in-place):
    module.iam.aws_iam_role_policy.node_extra        mysql/* prefix 추가
    aws_s3_bucket_lifecycle_configuration.shared     expire-mysql-backups 규칙 추가

  확인:
    aws iam get-role-policy --role-name cardinal-prod-node-role \
      --policy-name cardinal-prod-node-extra | grep mysql


배포
----------------------------------------------------------------------
1. kubectl apply -f cronjob.yaml

// 스케줄을 기다리지 말고 즉시 한 번 돌려 확인한다
2. kubectl -n database create job mysql-backup-manual --from=cronjob/mysql-backup

3. kubectl -n database logs job/mysql-backup-manual -c dump
   kubectl -n database logs job/mysql-backup-manual -c upload
   → "uploaded s3://cardinal-prod-shared-.../mysql/cardinal-....sql.gz"

4. aws s3 ls s3://cardinal-prod-shared-000034487830/mysql/

// 확인 후 수동 Job 정리
5. kubectl -n database delete job mysql-backup-manual


복구
----------------------------------------------------------------------
1. aws s3 ls s3://cardinal-prod-shared-000034487830/mysql/     # 시점 고르기
2. aws s3 cp s3://.../mysql/cardinal-2026-09-01-0330.sql.gz .
3. gunzip -c cardinal-2026-09-01-0330.sql.gz | \
     kubectl -n database exec -i deploy/mysql -- \
       sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -u root'

   ※ 덤프에 CREATE DATABASE / USE cardinal 이 들어 있어(--databases) DB 지정이 필요 없다.
   ※ 덮어쓰기다. 복구 전에 현재 상태를 한 번 더 덤프해 둘 것.


수동 덤프 (지금 당장 한 번 뜨고 싶을 때)
----------------------------------------------------------------------
CronJob 을 올리기 전이라도, 개발팀에게 DB 를 열어주기 전에는 반드시 한 번 뜬다.

  kubectl -n database exec deploy/mysql -- \
    sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -u root \
           --single-transaction --databases cardinal' \
    > backup-$(date +%F).sql

  리다이렉션(>)은 컨테이너 안이 아니라 이 명령을 친 곳에서 일어난다.
  즉 파일은 CP 에 떨어진다.


주의사항
----------------------------------------------------------------------
- --single-transaction 을 빼면 안 된다. 덤프 동안 테이블이 잠겨 서비스가 멈춘다.
  InnoDB 라 이 옵션으로 잠금 없이 일관된 시점을 뜰 수 있다.

- --databases cardinal 이라 MySQL 계정 정보(mysql 시스템 DB)는 백업되지 않는다.
  계정은 mysql/setup.txt 와 dev-access/setup.txt 에 생성 SQL 이 적혀 있으니
  복구 시 그걸로 다시 만든다. 데이터가 아니라 설정이므로 이 편이 낫다.

- 보존 기간 30일 (terraform 의 mysql_backup_retention_days). S3 lifecycle 이
  자동 삭제하므로 따로 정리할 것이 없다. 축제가 끝나고 데이터를 오래 보관해야
  하면, 만료 전에 마지막 덤프를 다른 곳으로 옮겨둘 것.

- 업로드는 노드 인스턴스 프로파일로 인증한다(IRSA 없음). system 노드의
  http_put_response_hop_limit = 2 가 전제다. 이걸 1로 되돌리면 파드에서 IMDS 에
  닿지 못해 upload 컨테이너가 실패한다.

- 덤프는 emptyDir(노드 루트 디스크)에 잠깐 떨어졌다 사라진다. /mnt/data 에 두면
  원본과 같은 EBS 라 백업의 의미가 없어진다.

- 백업 파일에는 전체 데이터가 평문으로 들어 있다. 버킷은 SSE-S3 암호화 +
  퍼블릭 차단 + HTTP 접근 Deny 가 걸려 있지만, 노드에 들어갈 수 있는 사람은
  읽을 수 있다. 개발팀 IAM 그룹에는 S3 권한을 주지 않았다.

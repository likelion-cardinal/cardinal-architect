RabbitMQ 설치 (단일 인스턴스, hostPath on EBS)
======================================================================
(이 디렉토리에서 실행)

// 네임스페이스는 mysql 에서 이미 만들었다. 없으면 먼저 생성
1. kubectl get ns database || kubectl create namespace database

// 비밀번호 설정 (계정명 cardinal 은 매니페스트에 평문)
2. kubectl -n database create secret generic rabbitmq-secret \
     --from-literal=password=<rabbitmq 비밀번호>

   ※ app-node/application 의 app-secret 에 넣는 RABBITMQ_PASSWORD 와
     반드시 같은 값이어야 한다.

// 배포
3. kubectl apply -f .

// 기동 확인 (첫 부팅은 30초쯤 걸린다)
4. kubectl -n database rollout status deployment/rabbitmq

// 상태 확인
5. kubectl -n database exec deploy/rabbitmq -- rabbitmqctl list_queues


관리 콘솔 보기 (필요할 때만)
----------------------------------------------------------------------
kubectl -n database port-forward svc/rabbitmq 15672:15672
→ http://localhost:15672  (cardinal / 위에서 정한 비밀번호)

Ingress 로 외부에 열지 말 것. 관리 콘솔은 큐 조작이 전부 가능하다.


애플리케이션에서 접속
----------------------------------------------------------------------
- 호스트: rabbitmq.database.svc.cluster.local  (AMQP 5672)
- 계정: cardinal / rabbitmq-secret 의 password


선행 조건 — terraform 데이터 EBS
----------------------------------------------------------------------
- mysql/setup.txt 와 동일하다. /mnt/data 가 EBS 마운트여야 한다.
  노드에서 확인: mountpoint -q /mnt/data && echo OK
- 하위 디렉토리 /mnt/data/rabbitmq 를 쓴다.
  같은 EBS(20GB)를 mysql·prometheus(5GB 상한)·grafana 와 나눠 쓴다.


주의사항
----------------------------------------------------------------------
- RABBITMQ_DEFAULT_USER / PASS 는 데이터 디렉토리가 비어 있을 때 최초 1회만
  적용된다. 이미 데이터가 있으면 무시되므로 비밀번호 변경은
    rabbitmqctl change_password cardinal <새 비밀번호>
  로 컨테이너 안에서 해야 한다. (mysql 과 같은 함정)
- hostname: rabbitmq 를 지우면 안 된다. 노드명이 바뀌어 기존 mnesia 디렉토리를
  못 찾고 큐가 전부 사라진 것처럼 보인다.
- replicas 를 2 이상으로 올리면 안 된다. 클러스터 구성(peer discovery)이 없어
  같은 hostPath 를 두 노드가 잡으면 mnesia 가 깨진다.
- 큐 durable / 메시지 persistent 설정은 애플리케이션 몫이다. 매니페스트가
  디스크를 붙여도 큐를 non-durable 로 선언하면 재시작 시 사라진다.

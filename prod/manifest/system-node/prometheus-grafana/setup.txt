모니터링 설치 (Prometheus + Grafana)
======================================================================
(이 디렉토리에서 실행)

// 네임스페이스 생성
1. kubectl create namespace monitoring

// Grafana admin 비밀번호 설정
2. kubectl -n monitoring create secret generic grafana-admin \
     --from-literal=password=<원하는 비밀번호>

// 전체 배포 (ingress.yaml 포함)
3. kubectl apply -f .

// node-exporter (별도 디렉토리, 같은 monitoring 네임스페이스)
4. kubectl apply -f ../../all/node-exporter/


node-exporter 는 여기 없다
----------------------------------------------------------------------
manifest/all/node-exporter/ 로 옮겼다. CP·system·app 전 노드에 뜨는 DaemonSet이라
이 디렉토리(nodeSelector로 system 노드에만 뜨는 것들)의 성격과 맞지 않는다.

네임스페이스는 여전히 monitoring 을 공유하고, Prometheus는 경로가 아니라
서비스 디스커버리(role: endpoints, service_name == node-exporter)로 찾으므로
prometheus.yaml 은 고칠 필요가 없다. 위 1번을 건너뛰면 node-exporter apply 가
네임스페이스 없음으로 실패한다.


대시보드
----------------------------------------------------------------------
dashboard-nodes.yaml 이 "Cardinal — 노드 리소스"(uid: cardinal-nodes)를
프로비저닝한다. 3번 apply 에 같이 포함되므로 별도 임포트가 필요 없다.
  접속 후 Dashboards → Cardinal 폴더

  섹션   클러스터 합계 / CPU / 메모리 / 디스크 / 네트워크
  변수   상단 "노드" 드롭다운으로 전체·개별 전환 (기본 All)

allowUiUpdates: false 라 UI 에서 고쳐도 30초 뒤 파일 기준으로 되돌아간다.
바꾸려면 UI 에서 JSON 을 export 해 ConfigMap 에 반영하고 apply 할 것.

기성 대시보드가 더 필요하면 Grafana UI 에서 Import → 1860(Node Exporter Full).
단 그건 파일로 관리되지 않아 클러스터를 다시 만들면 사라진다.

값이 kubectl top 과 다른 게 정상이다:
  kubectl top    컨테이너 사용량 합 / 분모는 allocatable
  node-exporter  호스트 전체(커널·containerd·kubelet 포함) / 분모는 물리 총량


ingress.yaml 주의
----------------------------------------------------------------------
- ingress-nginx 가 먼저 떠 있어야 한다 (manifest/app-node/ingress-nginx/)
- 접속: http://<ALB DNS>/grafana
- rewrite-target 쓰면 안 됨. 프리픽스를 살려서 넘겨야 Grafana 가 인식한다
  (grafana.yaml 의 GF_SERVER_SERVE_FROM_SUB_PATH=true 와 짝)
- CSS 가 깨지면 위 env 두 개가 안 먹은 것
- apply 하는 순간 Grafana 가 인터넷에 공개됨. 원치 않으면 이 파일만 빼고 apply
- 도메인 사면 host: grafana.<도메인> + path: / 로 바꾸고 env 제거가 더 깔끔
  (ACM 인증서는 dns/main.tf:10 이 이미 *.도메인 커버)

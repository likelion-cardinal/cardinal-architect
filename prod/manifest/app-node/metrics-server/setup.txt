metrics-server 설치 (HPA 선행 조건)
======================================================================
(이 디렉토리에서 실행)

// 배포 (네임스페이스는 kube-system)
1. kubectl apply -k .

// 기동 대기
2. kubectl -n kube-system rollout status deploy/metrics-server

// API 등록 확인 — AVAILABLE 이 True 여야 한다
3. kubectl get apiservice v1beta1.metrics.k8s.io

// 실제 값이 나오는지
4. kubectl top nodes
   kubectl top pods -A


왜 필요한가
----------------------------------------------------------------------
Cluster Autoscaler 는 "Pending 파드"를 보고 노드를 늘린다. 파드 수를 늘리는 건
HPA 이고, HPA 는 metrics-server 가 주는 CPU/메모리 사용량으로 판단한다.

  부하 ↑ → HPA 가 replicas ↑ → 노드에 자리 없음(Pending) → CA 가 노드 ↑

metrics-server 가 없으면 HPA 의 TARGETS 가 <unknown> 으로 남고 스케일링이
아예 일어나지 않는다. 에러로 보이진 않으니 조용히 안 늘어난다 — 반드시 3~4번을
확인할 것.

대상 HPA: manifest/app-node/application/hpa.yaml (backend / frontend)


배치 — App 노드
----------------------------------------------------------------------
nodeSelector: cardinal.io/role=application

App ASG 는 min_size=1 이라 노드가 0대가 되는 일은 없다. metrics-server 는
최근 값만 메모리에 들고 있어(저장 없음) 파드가 다른 노드로 옮겨 떠도 잃을
데이터가 없다.

단, CA 가 그 노드를 줄이거나 ASG 가 노드를 교체하면 파드가 옮겨 뜨는 30~60초
동안 kubectl top 이 비고 HPA 의 TARGETS 가 <unknown> 이 된다. 그 사이 HPA 는
직전 replicas 를 유지할 뿐 잘못 줄이지는 않으므로 실질적인 위험은 없다.

PodDisruptionBudget 은 일부러 붙이지 않았다. 레플리카 1개짜리에 minAvailable:1
을 걸면 CA 가 그 파드를 못 쫓아내 노드 축소 자체가 영원히 막힌다.


버전
----------------------------------------------------------------------
클러스터 1.34.9 → metrics-server v0.8.0
metrics-server 는 CA 와 달리 마이너 버전을 맞출 필요는 없지만, 올릴 때는
릴리스 노트의 지원 매트릭스를 확인할 것.


주의
----------------------------------------------------------------------
- 원격 base 를 받으므로 CP 에서 github.com egress 가 필요하다.
  (ingress-nginx 는 raw.githubusercontent.com, 이쪽은 github.com/releases)
- apiservice 가 계속 False 면 API 서버 → metrics-server 파드 IP(10250) 경로
  문제다. Calico VXLAN(4789/udp)이 CP ↔ App 노드 사이에 열려 있는지 확인.
- --kubelet-insecure-tls 를 빼면 "x509: cannot validate certificate" 로
  kubectl top 이 실패한다.
- 리소스 요청은 기본값(100m/200Mi)을 그대로 쓴다.
